# Fixture set `mantis-64`

Unit-test scale: three frames spanning the focus sweep, small enough to assert on individual pixels in a test body.

Crop rect (x, y, w, h): **4064,2700,64,64** -- a 64x64 window taken from the same place in every frame.

Why this rect: Centred on the frame, at reader scale: the reference crop is 3.59x sharper (16-bit Laplacian variance) than the best single frame, so the window spans real focus variation. But with only frames 0, 30 and 60 kept, frame 02 is sharpest in 12 of 16 tiles (spread 1.30x) -- this is a reader fixture, not a fusion one.

## Frames

| NN | source frame | head64k_sha256 |
|---|---|---|
| 00 | `20260829-IMG_9800.tif` | `ff786ffc30e94f88` |
| 01 | `20260829-IMG_9830.tif` | `26089cb616934ad4` |
| 02 | `20260829-IMG_9860.tif` | `9715e5742dd936d2` |

`head64k_sha256` is the sha256 of each source frame's first 64 KiB, truncated to 16 hex characters. It pins the header and the leading strips; it is not a whole-file digest, because each source frame is 268 MB and hashing all 61 would read 16 GB to answer a provenance question.

`reference.tif` is the identical crop of `Mantis_Stacked.tif`, converted from big-endian to little-endian and to one strip per row like every other file here.

`reference-MM-rps8.tif` is that same crop again, left in `Mantis_Stacked.tif`'s own layout: **big-endian `MM`, RowsPerStrip=8** (64 rows -> 8 strips). It exists because normalizing every other fixture means nothing here would otherwise exercise the layout the reader actually meets on the real reference file. Read correctly it is sample-for-sample equal to `reference.tif`; on disk the two differ. A reader that returns the same pixels for both has handled byte order and multi-row strips.
