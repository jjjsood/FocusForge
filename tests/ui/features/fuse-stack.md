# Fuse a stack
Reach: open a folder with `Start: --open fixtures/mantis-64/frames` (3 frames of 64x64, finishes in seconds) or `fixtures/mantis-512/frames` (8 frames of 512x512, about 20 s), then press **Fuse stack** (`FFToolbar::fuse-button`). `--fuse-tabs 0` presses it on tab 0 at launch; the run is usually over (the Keep question waiting) before a step can look at it.
Sub-features: the not-fused state and what stays unavailable before a fuse (export, overlay), keep or discard the result (`AppWindow::divergence-warning`), a second kept result, fuse at launch, pause and resume, cancel, queued tab, the record of a cancelled run in the projects overview and **Run again**, retry after a failure (`FFToolbar::retry-button`, no journey step).
Ids: toolbar `FFToolbar::fuse-button`, `pause-button`, `resume-button`, `cancel-button`, `cancelling-button`, `retry-button`; bottom bar `FFBottomBar::status-text` (the stage word, "Paused", "No job running", "fused HH:MM"), `step-text`, `eta-text`, `progress-bar`, `overlay-toggle`; `FFModeSwitch::stacking-half`; the right dock's CHECKPOINTS list with `FFCheckpointPanel::empty-note` and `checkpoint-export`; tabs `FFTab::area` N (N counts from 0 in opening order); the projects overview `FFTabStrip::projects-button`, cards `FFProjectCard::card-area`.
Gotchas:
- `buttons AppWindow::toolbar` lists the toolbar's buttons (it exists in stacking mode, not in the editor); a greyed button's line starts with `x`. `buttons FFDock::checkpoint-panel` does the same for **Export image**.
- Needs: a fixture whose fuse runs for a minute or more, or a flag that slows the run, to make pause, queued and cancel readable step by step; until then 02 steps 17-23 are human only.
- Both fixtures end their fuse in the Keep/Discard dialog: with the default alignment the run leaves frames unregistered (for `mantis-512` the frames named `00.tif`, `01.tif`, `06.tif` and `07.tif`), and only then does the dialog appear. Journey 01 steps 5, 11, 15, 18 and journey 02 steps 1, 8, 12 depend on it; if the dialog does not appear, they fail. After **Keep** the app switches to the editor, so a journey clicks **STACKING** to see the CHECKPOINTS list; **Discard** leaves the mode alone.
- A modal blocks everything below it; **Fuse stack** stays visible behind it and a click on it does nothing (01 step 6).
- Before the first fuse, and after a discard, **Export image** is greyed and the **Overlay** toggle stays off. Both are read on the same screen as the "Not fused yet" card and the "None yet — fuse a stack" line.
- A second fuse after a kept result adds a second CHECKPOINTS row (01 step 17); a discarded fuse adds none (01 step 20).
- Needs: a fixture stack that registers fully, or a flag that turns alignment off, to reach the path where a fuse commits with no dialog (CHECKPOINTS gains a row, status "No job running", no click). No journey covers it.
- Needs: a real failed run (a stack the pipeline rejects) to reach `FFToolbar::retry-button` by clicks. `--toolbar-state failed` shows only a preview with no job behind it (**Retry**; status "Failed", "ETA —"); `--toolbar-state running` previews "Aligning", "42 of 61", "ETA 1:12". Neither fits a journey that runs real fuses, and a preview may be overwritten when the opened folder finishes loading. The previews `paused` and `cancelling` ("Cancelling…" greyed) exist too.
- A run cannot be watched step by step: `mantis-512` ends in about 20 s and a read-and-click step takes about 10 s, so pause, resume, queued and cancel are `(human only)` steps (02 steps 17-23), all done within the one run started at step 17. Everything the journey checks by screenshot happens after a run has ended.
- A fuse that ends in the Keep question belongs to its tab: with `--fuse-tabs 0` the question is raised for tab 0 and shows only while tab 0 is selected, and clicking a tab or **Projects** while it is open does nothing (02 steps 2, 3). The second tab stays unfused, with its own question later (02 step 12: "00.tif and 02.tif could not be aligned").
- Tab order is `--open` order: `FFTab::area` 0 is `mantis-512` (8 frames), 1 is `mantis-64` (3 frames).
- **Fuse stack** reads "Queued" on an idle tab while another tab runs (02 step 19, human only) and "Fuse stack" again once nothing runs. Cancel the queued tab before the running one: cancelling the running one lets the queued tab start. `--fuse-tabs 0,1` was seen to leave tab 1 unfused once tab 0 reached its Keep question (the queued press was dropped), so the journey starts only tab 0.
- Cancelling shows a disabled "Cancelling…" button for a moment before **Fuse stack** returns. The cancelled card's stage line reads "STOPPED WHILE FUSING" (or the stage the run was in), so step 22 checks only its start; a cancelled tab with an earlier kept result still reads "8 frames · 1 checkpoint".
- **Run again** has no id of its own; it sits in the card inside `AppWindow::projects-overlay` and is found by its label (`click "Run again" AppWindow::projects-overlay`).
- Opening a folder raises the stack-grouping question only when its frames fall into several stacks (capture times more than 60 s apart). The mantis fixtures are one stack, so no such question is expected.
