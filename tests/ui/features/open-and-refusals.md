# Open and refusals
Reach: open inputs with `Start: --open <folder or .ffp>`. The flag is repeatable and each path is opened in order, so one launch can mix successful opens with a refusal; the native **Open folder…** chooser and dropping a folder are human only. A load runs on a worker; every question, refusal and notice below appears within a few seconds of launch over the opened tabs or the empty window.
Sub-features: refusal "No frames here" (`AppWindow::refusal-dialog`, button "Pick another folder…"); refusal "This project cannot be opened" (same dialog, button "Close"); refusal "These are not the project's frames" (same dialog, after **Locate frames…** on the wrong folder); grouping question (`AppWindow::grouping-question`: "This folder reads as N stacks of M frames.", "Open as one project", "Open as N projects", "Cancel"); skipped-subfolder record ("Some images were skipped", message "N subfolder(s) skipped" with the paths, shown as a toast and in the notification center); fingerprint mismatch (`AppWindow::mismatch-dialog`: "The source frames are not the same", Cancel, "Locate frames…", "Open anyway"); missing sources (`AppWindow::sources-missing-dialog`: "The frames are no longer there", "Close", "Locate frames…"); crash record ("Previous session stopped", a toast and a notification-center row with **Acknowledge** and **Diagnostics**, covered by 15-notification-center.md steps 29-35); loading indicator ("Loading…"); RAW folder as a one-frame project; compressed TIFF variants; the empty start after the last tab closes.
Ids: dialogs are click targets by label within their `AppWindow::` id (the buttons are plain rectangles, not named); `FFTabStrip::projects-button`; `FFTab::close-area` N; a toast is `AppWindow::toast`, its close glyph `FFToast::close` (**Dismiss notification**) and its body `FFToast::card`; one toast shows at a time, so each has one match, number 0; the bell is `FFIconBar::bell`.
Gotchas:
- Every dialog here is modal and has exactly the buttons listed: the dimmed area and **Projects** do nothing while it is up .
- A folder with no frames (`fixtures/retouch`) gives the dialog "No frames here" and also a "Not a project" card (titled with the folder name, "LEFT ALONE", "not read · not changed") in the Projects overlay, whose count then reads "N · 1 did not open" with N counting the open projects too. It never gives a card alone. Its button is the only dismissal and it opens the system chooser on the window's own thread (human only, and nothing after it can be driven until the chooser is cancelled); the other refusals' button is "Close" and just dismisses. The refusal is raised at launch and stands over everything after it until the chooser is cancelled by hand, so no journey opens a folder without frames: it is a human check, blocked until a refusal can be dismissed without the chooser.
- The failure card stays after every tab is closed.
- A folder holding `frames/` is read through it, and its other subfolders are never walked (so `fixtures/mantis-64`, `mantis-512` with `golden/`, and every `mantis-64-<compression>` variant open with no notice and no card). Reference TIFFs beside `frames/` are ignored.
- `fixtures/blackmagic-micro-dng` opens as a one-frame project named "frame" (card second line "1 frame · no checkpoint yet"), not as a refusal: RAW extensions count as frames, although the refusal text says "16-bit TIFF". Journey 12 steps 2-4 assert the pane label "frame.dng" and the counts, not the picture (the pane stays black). **Fuse stack** is greyed with this one frame (step 5, read with `buttons AppWindow::toolbar`).
- The 24 `mantis-64-<codec>-<p1|p2>-<strip|tile>-<ii|mm>` variants all hold `frames/00.tif`..`02.tif` plus `reference.tif`; one stands for all (journey 12 steps 6-11). The fuse ends in the Keep question like any fixture fuse.
- Opening several folders in one launch makes the last successful one the current tab; a refused one never changes the current tab. With `--open fixtures/blackmagic-micro-dng --open fixtures/mantis-64-lzw-p2-tile-mm` the cards read "frame" (1 frame) then "mantis-64-lzw-p2-tile-mm" (3 frames) and the "CURRENT" chip sits on the second; the overview stays open until a card or the **Projects** button closes it, so a step that clicks a card needs it open.
- A toast shows only while the window holds keyboard focus (otherwise the record becomes a desktop banner), so every toast step is human only; the same record is read through the bell and the notification center. An info toast stays 6 s, a crash toast 10 s, and pointer hover holds it.
- The loading indicator ("Loading…" with a spinner over the canvas) appears only for a load longer than 500 ms; every fixture opens faster, so it never shows and cannot be observed. Needs a folder whose header walk takes more than 1 s (hundreds of frames); not buildable from the checked-in fixtures.
- Not covered for lack of a fixture: grouping question **Cancel** (dialog gone, "No project open"); the crash toast's **Dismiss notification**; **Locate frames…** on the mismatch dialog (human only); mismatch **Cancel**.
Needs (fixtures not yet in `fixtures/`, each registered in the fixture manifest like the others):
- `fixtures/mantis-64-notes/`: `00.tif`, `01.tif`, `02.tif` copied from `mantis-64/frames` straight in the folder root (no `frames/`), plus a subfolder `notes/` holding only `readme.txt`. The walk finds the folder as one stack and `notes/` as a subfolder without frames: "1 subfolder skipped" and a "Not a project" card "notes". Unlocks: open it, read "1 subfolder skipped" over the left pane with the dock header "3 frames · 0 excluded", see the overlay count "2 · 1 did not open", read the record "Some images were skipped" in the notification center (`FFIconBar::bell`).
- `fixtures/mantis-64-two-stacks/`: subfolders `a/` and `b/`, each holding `00.tif`, `01.tif`, `02.tif` copied from `mantis-64/frames`, nothing in the root and no `frames/` anywhere. Two frame-bearing directories give two groups: "This folder reads as 2 stacks of 6 frames." (a capture-time gap above 60 s inside one directory would split it too). Unlocks the grouping question: the dimmed area leaves it on screen, **Open as 2 projects** gives 2 tabs and "2 open", **Open as one project** gives 1 tab with "6 frames · 0 excluded".
- `fixtures/projects/corrupt.ffp`: any short non-archive bytes with the `.ffp` extension. Gives "This file is not a FocusForge project." under the title "This project cannot be opened" with one button "Close" that returns to "No project open". (A real project file cut off halfway would give "The file was cut short — it ends before the project does.")
- `fixtures/projects/mismatch.ffp`: a valid saved project over 3 frames, whose recorded frames resolve beside it to files that exist but differ (for example `fixtures/projects/mismatch-frames/` with `01.tif` and `02.tif` swapped). Unlocks the mismatch dialog headed by "mismatch.ffp" and **Open anyway** giving 1 tab with "3 frames · 0 excluded".
- `fixtures/projects/missing.ffp`: a valid saved project over 3 frames whose recorded frame path does not exist anywhere under `fixtures/`. Unlocks "The frames are no longer there" ("A project remembers its frames by path. 3 of 3 cannot be found in this location."), **Close** leaving 1 tab, a "Sources missing" card with **Locate frames…**. The wrong-folder step needs `fixtures/mantis-512/frames`, already present; its exact refusal text ("N of 3 frames in this folder differ from the ones this project was made over", or "N of 3 cannot be found in this folder") is not asserted.
- Crash record: the launcher sets `FOCUSFORGE_DATA_DIR=<scratch>` (the app reads `<scratch>/focusforge/crashes/`) with one file `20260918T010203Z-focusforge-7.json` holding `{"format":1,"payload":"boom"}` and no `.reported` marker, as a copy per run: **Acknowledge** in the notification center writes `<stem>.reported` beside it, so the checked-in seed must not be the folder used. Every other run needs `FOCUSFORGE_DATA_DIR` pointing at an empty scratch folder, else a real crash left on the machine raises the crash record over it. Unlocks: **Diagnostics** on the record opens "Settings" on Diagnostics with the label "Save to".
