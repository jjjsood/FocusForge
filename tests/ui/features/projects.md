# Projects
Reach: press the **Projects** button in the tab strip (`FFTabStrip::projects-button`; the same button closes it, as does Esc). `Start: --projects-overlay` opens it at launch and it stays open once an `--open` load lands (with `--fuse-tabs` it opens once the last run settles). An overview opened before a load starts still closes when that load lands, so the journey, which opens two folders, clicks the button instead.
Sub-features: gallery cards (picture, name, second line "N frames · no checkpoint yet" / "N frames · N checkpoints", chips "UNSAVED" and "CURRENT"), switching tab by clicking a card (the overview closes), closing a project from its card (hover shows a close glyph top-right), rail actions **New project** (Ctrl+N), **Open project…** (Ctrl+O), **Save project** (Ctrl+S, dimmed unless the active project has something to write), **Close project** (Ctrl+W, closes the active tab), the RECENT list (up to 5 rows: name, folder, "today" / "yesterday" / "D Mon"), failure cards ("Cancelled" and "Did not stack" with **Run again**, "Sources missing" with **Locate frames…**, "Not a project").
Ids: `AppWindow::projects-overlay`, `FFProjectCard::card-area` N (N counts cards from 0: open projects in tab order, then "Not a project" cards), `FFProjectCard::close` (label **Close**, present only while an opened card is hovered), the rail entries `FFProjectsRail::new-project`, `open-project`, `save-project`, `close-project` and `recent-row` N. Card buttons (**Run again**, **Locate frames…**) are reached by label inside `AppWindow::projects-overlay`. The tab strip stays above the overlay, so `FFTab::close-area` N still closes a tab while it is open.
Gotchas:
- The heading reads "Open projects" and the count "N open" while every open succeeded; once a failure card exists they read "Projects" and "N · M did not open". A cancelled run is a card of an open project (it counts in "N open"), not a failure card.
- Every card of a freshly opened folder carries "UNSAVED" (nothing is sealed to disk); two folders both named `frames` give two cards with the same name, so journeys tell them apart by their frame count. The first `--open` is card 0; the last opened project is the current one.
- Clicking a card of an open project switches to it and closes the overview; clicking a "Not a project" card does nothing. **Close project** and the card close glyph leave the overview open. Closing a project with a checkpoint asks "Save this state first?" (`AppWindow::close-guard`); closing one with nothing unsaved is immediate.
- A cancelled run is a card of an open project (it counts in "N open"): headed "Cancelled", stage "STOPPED WHILE FUSING", "You stopped this one. Nothing was written.", button **Run again**. Journey 11 cannot reach it without a race, so it is covered by journey 02 steps 22-23 (human only). **Run again** does nothing while any run is live.
- The overview covers everything below the tab strip, so the toolbar and dock cannot be clicked while it is open.
- Rail entries have ids and read as buttons in `buttons AppWindow::projects-overlay`; **Close project** is clicked by id (11 steps 17 and 22), while **New project** and **Open project…** open a native chooser and stay `(human only)` (11 steps 23-24). The card close glyph appears only while the pointer rests on an opened card: 11 step 20 hovers the card (`FFProjectCard::card-area` 0), then step 21 clicks `FFProjectCard::close`. "Save project" reads greyed (`x`) with no project open (11 step 22).
- Saves land in the launch's `--save-folder` (a run by hand passes a fresh one too), so **Save project** (11 step 16) opens no chooser and writes `frames.ffp` there. A saved project's card has no "UNSAVED" chip, and a saved project closes at once with no guard. Clicking a RECENT row reopens the project and closes the overview (11 step 18); the row exists only for a project saved or opened in this run, because every run starts with an empty `[recent]` list. Never save an opened fixture project: it writes back into `fixtures/`.
- Human only: Ctrl+N, Ctrl+O, Ctrl+S, Ctrl+W and Esc on the overview (no journey presses them), the native folder and file choosers.
- The "Not a project" card for a skipped subfolder is read in 16 step 8 (`fixtures/open-root-and-subfolder`, below the fold of a 7-card overview). The "No frames here" folder's card, "retouch", is read in 12 steps 4 and 18 (Escape dismisses the dialog first, 12 step 3); it counts in the overview's "N · 1 did not open".
- Journey 18 launches with `--projects-overlay --toolbar-state paused` and two `--open` paths: the overview is up once both folders have loaded (18 step 1) and Esc closes it (18 steps 3, 16 and 19). `--toolbar-state paused` is a held preview, not a run: the toolbar reads **Resume** and **Cancel** with no **Fuse stack**, the bottom bar "Paused" with "ETA —", and both buttons do nothing (18 steps 4, 5 and 20). The preview survives tab, dock, zoom, overview and close-project changes; only a real run replaces it, and no step can start one because **Fuse stack** is absent while it is held.
