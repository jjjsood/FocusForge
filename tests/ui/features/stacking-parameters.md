# Stacking parameters
Reach: open a folder (`--open`), then click **Settings** (`FFDockTabs::settings-tab`) in the right dock, or start with `--dock-tab settings`. The tabs are only shown in stacking mode with a project open.
Sub-features: four sections PREPARE, FUSE, ALIGN, FINISH, each with a "DEFAULT" badge until one of its values is set; **Reset All to Default** (greyed until a value is set); the algorithm menu under FUSE ("Details", "Soft transitions", "Focus map") and under ALIGN ("Pyramidal ECC"); **More...** fold-outs holding the advanced rows; the ALIGN **Enabled** switch; menu rows (ALIGN "Mode"); settings kept separately per project tab; the panel locked while a fuse runs.
Ids: `FFMenu::area`, `FFMenuList::option-area`, `FFMoreToggle::header-area`, `FFToggle::area`, `FFSlider::drag-area`, `FFResetAll::area`, `FFScrollbar::track-area`, `FFTab::area`.
Gotchas:
- Row ids count only the controls inside the visible part of the panel: a row scrolled out of view is absent, and an open menu list counts only its own entries (`FFMenuList::option-area` 0 to 2 for the FUSE list, 0 and 1 for a Mode list, none while closed). Assumed state at launch: FUSE "Details", every More... closed, ALIGN enabled, panel scrolled to the top. Then `FFMenu::area` 0 is the FUSE Algorithm field and 1 the ALIGN one (an opened ALIGN More... adds Mode as 2); `FFToggle::area` 0 is ALIGN Enabled (an opened PREPARE More... puts "Equalize brightness" first); `FFMoreToggle::header-area` 0, 1, 2 are PREPARE, FUSE, ALIGN while all three are in view (an open fold-out pushes the headers below it out of view, so close a fold-out before using the next one); `FFSlider::drag-area` numbers the panel's sliders top to bottom, the bottom bar's overlay slider last. Scrolled to the end (ALIGN More... closed), `FFToggle::area` 0 is ALIGN Enabled, 1 is Auto-crop and 2 the overlay switch. Scrolled to the middle (`1193 480`, ALIGN More... open), `FFMenu::area` 0 is the ALIGN Algorithm field and 1 the Mode field.
- **Reset All to Default** and the rows below the fold are absent from the element tree until scrolled: there is no wheel, so drag `FFScrollbar::track-area` 0 to the bottom (`1193 705`), to the middle (`1193 480`) or back to the top (`1193 225`). The scroll position stays when another project tab is selected. Whether **Reset All to Default** is enabled is read from the screenshot (orange label enabled, grey label disabled): it is not in the button list, and `buttons` finds none of the panel's controls. The wheel scroll itself is human only.
- A slider is set by clicking the middle of its track (`FFSlider::drag-area`), which sets the half-way value: Radius 8 of 0 to 16, Sharp-source preference about 4.5 of 1 to 8. Typing a value into a field is human only.
- Defaults seen at launch: FUSE "Details" has no row outside More... (only "Levels", whose default is derived from the image size); "Soft transitions" shows "Sharp-source preference" 4 and, under More..., "Radius" 16; "Focus map" has under More... "Score Radius" 4 and "Smoothing Radius" 8; PREPARE holds only More... ("Equalize brightness" on, "Max brightness gain" 1.25); ALIGN holds "Enabled", the "Algorithm" menu and More... ("Mode" Rotation + Scale, "Max Iterations" 400, "Epsilon (px)", "Pyramid Depth", "Reference Policy", "Reference Frame"); FINISH holds "Auto-crop" (on).
- Picking another algorithm changes no value, so it keeps the section at "DEFAULT"; **Reset All to Default** clears values but keeps the chosen algorithm. The open More... folds stay open after a reset and across an algorithm switch.
- A value set to what the default already is still counts as set: the badge stays gone.
- The ALIGN heading reads only the algorithm's own values: switching ALIGN **Enabled** off leaves the ALIGN badge and keeps **Reset All to Default** greyed. Greyed ALIGN rows are inert: clicks on them report success and change nothing.
- While a fuse runs the whole panel is dimmed and inert, and stays so while the run is paused. A fixture run ends in about 20 seconds, so starting it and pausing it is a race a step-by-step run loses: those steps are human only.
- The picker lists only real algorithms in a normal build; a developer build with the test algorithms lists "Dummy Stack (test-only)" (id "dummy-stack") as the second FUSE entry, between "Details" and "Soft transitions", so "Soft transitions" is option 2 and "Focus map" option 3 instead of 1 and 2. Picking it swaps the FUSE rows for "Threshold", "Mode" and "Workers". The guide names the entries by their grey ids and gives both option numbers.
- Human only: typing a value into a field, the scroll wheel in the panel, judging that a changed parameter changes the fused pixels.
