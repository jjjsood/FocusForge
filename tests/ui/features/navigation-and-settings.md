# Navigation
Reach: open one or two folders (`--open`, repeatable); the dock tabs, canvas, bottom bar and tab strip are on screen at once. A fuse is started from the toolbar and ends in the keep question.
Sub-features: the "+" pseudo-tab, dock tabs (**Images** / **Settings**), frame selection by clicking a row in the list, several open projects as tabs, zoom (zoom in, zoom out, **Fit**) and its minimum, the settings window blocking the main window, the Z-map overlay (toggle and slider in the bottom bar) before and after a fuse, moving a pane into its own window and back.
Gotchas: the left pane label shows the selected frame's file name ("00.tif"); the zoom readout is "—" with no project and shows a percentage once the image is fitted; both fixture folders are named `frames`, so tab titles do not tell the tabs apart, the dock header ("3 frames · 0 excluded" against "8 frames · 0 excluded") does. `FFTab::area` N is the Nth tab from the left; `FFUndockControl::area` 0 is the left pane and 1 the Composite pane (two instances while both panes are docked). The overlay toggle is `FFToggle::area` 0 while no Settings window is open; the Settings window's own first switch is then instance 1. The overlay toggle and slider are dimmed and inert until the active tab holds a finished fuse; the slider starts at 65%. The bottom-bar overlay slider is the only `FFSlider::drag-area` in the stacking view (instance 0); the window size varies between launches (1200x760 seen), so a drag to window point 1120,678 lands on or past the track's right end and the value ends above 65%. The fixtures never align fully, so a fuse ends in the keep question (`AppWindow::divergence-warning`): answer **Keep** first, then click **STACKING** to get the stacking view back. A click behind a modal (the Settings window, the keep question) still reports success: judge it by the screenshot. While one pane is detached, the other pane's undock control is hidden, not dimmed. An id is found in whichever window holds it; `FFUndockControl::area` is in both windows, so a step on it in the second window passes `--window N`. The second window is the last entry of `list_windows` (a closed window's entry stays listed, so the index grows with every reopen; an unscoped id lookup skips the closed one): `shot <png> N --scale 0.5` shows it, and its close (`FFWindowBar::close`, only in this window) and "Dock pane" (`FFUndockControl::area`, `--window N`) controls are clicked by id. Zoom steps run on the 8-frame project: the 3-frame project fits at about 700 % or more, above the 500 % ladder top, so **Zoom in** does nothing there. The drag on an enabled overlay slider can take a while; the call returns when the gesture has finished, and the value has already changed. Human only: scroll-wheel zoom and pan, Ctrl+wheel to step the source frame, middle-button or Space drag pan, dragging, minimising or maximising a window.
The "+" box after the last tab (`FFTabStrip::plus-button`, no accessible label) selects a pseudo-tab: the canvas shows "No project open" and the bottom bar the same text, every project tab stays in the strip but none is selected, and a click on a tab (`FFTab::area` N) brings its project back (07 steps 8-9). When the tabs outgrow the strip, scroll arrows (`FFTabStrip::left-arrow`, `FFTabStrip::right-arrow`) appear and "+" is pinned at the right end of the strip; the fixtures open too few tabs to reach that, so the arrows are not covered. `FFTab::area` N still counts from 0 in opening order for tabs scrolled out of view.
