# Retouch (editor mode)
Reach: open a folder and fuse it (`--open`, `--fuse-tabs 0`). A kept fuse enters the editor by itself, where the dock shows the Images list with no **Images**/**Settings** tabs (they exist in STACKING mode only); `--enter-editor` selects it once the run has settled. **STACKING** and **EDITOR** (`FFModeSwitch`) switch the toolbar and dock between the two modes at any time.
Sub-features: brush size and softness (log and linear sliders), soft strokes painted from the selected frame onto the Composite, undo and redo, saving the strokes as a checkpoint, the "Save your edits first?" question when fusing again over strokes (Cancel, Fuse anyway), the "Save this state first?" question when restoring a checkpoint over strokes (Cancel, Discard and restore), choosing the source frame in the Images list, the pipette button, selecting and deleting a checkpoint.
Gotchas:
- A fixture fuse on `mantis-64` ends in `AppWindow::divergence-warning`; the editor opens after **Keep**, and `--enter-editor` waits behind that dialog. Journey 03 starts with that **Keep**. Journey 04 launches with `--fuse-tabs 0,0`: the second press waits for the first Keep question to be answered (no second run while it is up), then runs on its own and asks its own Keep question, so two **Keep** clicks give two checkpoints (journey 04 steps 1-3). A **Fuse anyway** run that is then discarded (journey 04 steps 13-14) adds no row and keeps the stroke.
- Pipette, undo and redo are icon buttons in `AppWindow::editor-toolbar`, in this order, with the ids `FFEditorToolbar::pipette`, `FFEditorToolbar::undo` and `FFEditorToolbar::redo` and the labels **Pipette**, **Undo** and **Redo**. Read their state with `buttons AppWindow::editor-toolbar` (a greyed button's line starts with `x`; the armed pipette reads checked=true). In STACKING mode the three ids do not exist.
- Undo, redo and **Save checkpoint** are enabled only after a stroke; they read as greyed out before it. Redo is enabled only after an undo, and a new stroke after an undo makes it greyed out again (03 steps 22-27). A greyed control is read from `buttons`, not from a screenshot.
- Saving a checkpoint also greys out undo and redo (03 step 29). In STACKING mode the toolbar has the **Fuse stack** button, no Size and Soft, and **Save checkpoint** is plain grey text, not a button; the real **Save checkpoint** button exists only in the editor toolbar (03 steps 2-6).
- Window points are logical points, equal to the pixels of a `--scale 0.5` screenshot (do not repeat `--size` in `Start:`). Toolbar controls sit at y = 56; the Size track runs x 56-128, the Soft track x 236-308; Size is logarithmic, 1 to the image's shorter side (60 on `mantis-64`, whose fused result is cropped), shown as a whole number, Soft is linear, shown as "N%". The sliders are `FFSlider::drag-area` 0 (Size) and 1 (Soft); a third one (2) is the Overlay slider in the bottom bar. A stroke from the Composite's centre to 1000,400 is one press, one move and one release; the app paints it in well under a second, but the driver's `drag` call takes about 9 s on a debug build because it synthesizes the motion itself, longer for a longer drag (a long drag from a slider to 1000,400 took 27 s), and prints `landed after N s` only when a drag outlasts the 60 s request limit; read `buttons` afterwards (undo and **Save checkpoint** turn enabled). A drag on the Composite in STACKING mode takes just as long, paints nothing and leaves the next click working; a journey still only clicks there (03 step 3).
- The fuse-again question appears only when strokes exist and **Fuse stack** is pressed (in STACKING mode); its text is "Fusing frames" over "1 unsaved brush stroke will be lost." and the buttons are Cancel, Save and fuse, Fuse anyway, all inside `AppWindow::close-guard`. The restore question is the same dialog with title "Save this state first?", context "Restoring <algorithm> · <HH:MM:SS>" and buttons Cancel, Save first, then restore, Discard and restore. A native file chooser follows **Save and fuse** and **Save first, then restore** on an unsaved project: human only, no journey covers it.
- Checkpoint rows are `FFCheckpointRow::area N` (N counts from 0 in list order, newest first, separators excluded). The red trash icon is `FFCheckpointRow::trash` (label **Delete checkpoint**); it exists only while the pointer is over a row and only while the list holds 2 or more rows, and `buttons FFDock::checkpoint-panel` lists it then. A pointer rest is a `Hover` on the row (04 steps 21, 24 and 27: `hover FFCheckpointRow::area 0`); a click on another control moves the pointer off the row, so 04 step 24 hovers again before the second trash click. Cancel of any of these questions leaves strokes, rows and selection untouched.
- The pipette's state is checked=true on `FFEditorToolbar::pipette` while armed (03 steps 18-19); the pixel it picks and the stroke's pixels are human only. Alt+click in the Composite picks the source frame under the point and leaves the pipette off (03 step 20: `click-id FFCanvas::pane-right --hold Alt`).
- Human only, no journey step: Ctrl+Z and Ctrl+Shift+Z, Shift+wheel brush size, multi-segment strokes, and judging the pixels of a stroke. The tab's "UNSAVED" chip is lit from the first fuse, so it does not mark a stroke.
- A camera-RAW stack runs the same editor path in `manual/03-editor-brush-raw.md` (three real DNG files copied into `.scratch/raw-gui/frames`, so no numbered journey can start from it): the fuse ends without a "Keep this fused result?" question, a saved project reopens in STACKING mode with its two checkpoints and shows its Composite after one **Fit** click, and the Size slider keeps its last value across the reopen.
