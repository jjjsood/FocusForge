# Retouch (editor mode)
Reach: open a folder and fuse it (`--open`, `--fuse-tabs 0`). A kept fuse enters the editor by itself, where the dock shows the Images list with no **Images**/**Settings** tabs (they exist in STACKING mode only); `--enter-editor` selects it once the run has settled. **STACKING** and **EDITOR** (`FFModeSwitch`) switch the toolbar and dock between the two modes at any time.
Sub-features: brush size and softness (log and linear sliders), soft strokes painted from the selected frame onto the Composite, undo and redo, saving the strokes as a checkpoint, the "Save your edits first?" question when fusing again over strokes (Cancel, Fuse anyway), the "Save this state first?" question when restoring a checkpoint over strokes (Cancel, Discard and restore), choosing the source frame in the Images list, the pipette button, selecting and deleting a checkpoint.
Gotchas:
- A fixture fuse on `mantis-64` ends in `AppWindow::divergence-warning`; the editor opens after **Keep**, and `--enter-editor` waits behind that dialog. Both journeys start with that **Keep**. A second checkpoint needs a second fuse: **STACKING**, **Fuse stack**, **Keep** (journey 04 steps 7-10).
- Undo, redo and the pipette are unlabelled icon buttons in `AppWindow::editor-toolbar`, in this order: eyedropper (pipette), left-turning arrow (undo), right-turning arrow (redo). Read their state with `buttons AppWindow::editor-toolbar`. The window-wide `FFIconButton::area` numbers in editor mode are 0-2 the tab strip's window buttons, 3 pipette, 4 undo, 5 redo, 6-7 the bottom bar's zoom buttons (8 in all, checked live); in STACKING mode the three toolbar numbers do not exist.
- Undo, redo and **Save checkpoint** are enabled only after a stroke; they read as greyed out before it. Redo is enabled only after an undo, and a new stroke after an undo makes it greyed out again (03 steps 22-27). A greyed control is read from `buttons`, not from a screenshot.
- Saving a checkpoint also greys out undo and redo (03 step 29). In STACKING mode the toolbar has the **Fuse stack** button, no Size and Soft, and **Save checkpoint** is plain grey text, not a button; the real **Save checkpoint** button exists only in the editor toolbar (03 steps 2-6).
- Window points are logical points, equal to the pixels of a `--scale 0.5` screenshot (do not repeat `--size` in `Start:`). Toolbar controls sit at y = 56; the Size track runs x 56-128, the Soft track x 236-308; Size is logarithmic, 1 to the image's shorter side (60 on `mantis-64`, whose fused result is cropped), shown as a whole number, Soft is linear, shown as "N%". The sliders are `FFSlider::drag-area` 0 (Size) and 1 (Soft); a third one (2) is the Overlay slider in the bottom bar. A stroke from the Composite's centre to 1000,400 is one press, one move and one release; the app takes up to a minute to paint it, so the driver's drag request can time out while the stroke still lands: read `buttons` again afterwards (undo and **Save checkpoint** turn enabled). A drag on the Composite in STACKING mode also hangs for about a minute and swallows the next click, so a journey only clicks there (03 step 3).
- The fuse-again question appears only when strokes exist and **Fuse stack** is pressed (in STACKING mode); its text is "Fusing frames" over "1 unsaved brush stroke will be lost." and the buttons are Cancel, Save and fuse, Fuse anyway, all inside `AppWindow::close-guard`. The restore question is the same dialog with title "Save this state first?", context "Restoring <algorithm> · <HH:MM:SS>" and buttons Cancel, Save first, then restore, Discard and restore. A native file chooser follows **Save and fuse** and **Save first, then restore** on an unsaved project: human only, no journey covers it.
- Checkpoint rows are `FFCheckpointRow::area N` (N counts from 0 in list order, newest first, separators excluded). The red trash icon has no id, shows only while the pointer is over a row and only while the list holds 2 or more rows, so clicking it is `(human only)` in 04 steps 21-25. A pointer rest is reachable by a drag from another row (04 step 20: `drag FFCheckpointRow::area 1 1177 148`); the icon itself shows up as an `Image` descendant of the hovered row (`query_element_descendants` on `FFCheckpointRow::area` 0, then `click_element` on it) and opens the delete dialog, which is how the delete steps were checked by hand. Cancel of any of these questions leaves strokes, rows and selection untouched.
- The pipette's visible state is the accent fill of its button while armed; the pixel it picks and the stroke's pixels are human only.
- Human only, no journey step: Ctrl+Z and Ctrl+Shift+Z, Shift+wheel brush size, multi-segment strokes, and judging the pixels of a stroke. The tab's "UNSAVED" chip is lit from the first fuse, so it does not mark a stroke.
