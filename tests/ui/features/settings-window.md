# Settings window
Reach: click **Settings** (`FFIconBar::settings`) at the bottom of the icon bar on the left edge. The window is `AppWindow::settings-modal`; its close button is `FFSettingsModal::close` (**Close settings**); the rail entries are `FFNavRailEntry::area` N counting from 0 in the order Performance, Appearance, Storage, Input map, Diagnostics, About (indices from the rail's source order). Appearance is covered by 13-source-image-views.md.
Sub-features: Performance (GPU processing switch, Backend line, Host memory cap, VRAM cap, Host and VRAM budgets), Storage (LOCATIONS paths, Clear cache), Input map (read-only BINDINGS table), Diagnostics (file list, Include minidumps switch and warning, Save to, Create bundle), About (version, license, notice, source), closing the window, the GPU switch persisting across close and reopen, the Backend line after a fuse with the switch off.
Gotchas: only the open section's content exists in the window, so `FFToggle::area` 1 is the one switch on screen (Performance GPU switch or Diagnostics minidumps switch; instance 0 is the bottom-bar Overlay toggle). The switches have no text: on is the knob at the right end on an accent track, off is the knob at the left end on a grey track. "Backend" is a text row, not a menu, and is empty until a fuse has run; after a fuse with the GPU switch off it reads "cpu — GPU processing is off". "VRAM budget" reads "Not probed yet" until a fuse with the GPU on has run. Host budget and the Version text vary by machine and build. The window covers the whole main window as a modal: a click on the toolbar behind it reports success but does nothing. The GPU switch is saved in the settings file under `--config-dir`. The log, crash, scratch and bundle locations come from the environment's data folder, not from `--config-dir`; **Clear cache** and **Create bundle** act on that folder, so a guide only looks at them and never presses them. The cap fields are typed into with `Type` (`FFTextField::input` 0 is Host memory cap, 1 is VRAM cap; 08 steps 7-8); a valid VRAM cap shows its note "Caps only lower the probed budgets. Changes apply from the next start." only once the session's GPU budget has settled (a run has probed the GPU), so never in a launch that has not fused with the GPU on. Typing into "Save to" and opening the "Source" link are human only. Esc closes the window from any section, also after a text field in it held focus (08 step 23); it leaves a projects overview underneath open, and a second Esc closes that. The window is a fixed 680x520 panel with no scrollbar: every section fits in view (only the Diagnostics file list scrolls inside itself). The path texts under LOCATIONS and in "Save to" are cut off by their field width and start with "~/" or the config/data folder as given, so a guide asserts that a path text is shown, never its end; "not created yet" follows a folder that does not exist yet and varies by run. The Input map table has seven cells per column (`FFInputTableRow::input-cell` 0 is the header, 1 to 6 the rows).
