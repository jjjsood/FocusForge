# Checkpoints and export
Reach: open a folder (`--open`) and fuse it (`--fuse-tabs 0`, or `--fuse-tabs 0,0` for two fuses, or **Fuse stack**); the right dock's CHECKPOINTS list then holds one row per result, newest first, each an algorithm name over a HH:MM:SS time. **Export image** sits in the CHECKPOINTS heading row.
Sub-features: select a row (accent bar and raised background), delete a row (trash icon on hover, confirm), Export image dialog (format TIFF/PNG/JPEG, per-format settings, Metadata switch, settings menu, context line, Cancel; Export writes `<proposed name>.<format ext>` into the launch's `--save-folder`, with no chooser, when one is given; without it the native save dialog opens). Closing the dialog with Cancel discards every choice: the next opening shows TIFF, 16-bit, None and Metadata on.
Ids: `FFCheckpointPanel::checkpoint-export`, `FFCheckpointRow::area N`, `AppWindow::export-dialog`, `AppWindow::checkpoint-delete`; inside the export dialog `FFMenu::root N`, `FFMenuList::option-area N`, `FFToggle::area N`; dialog buttons (Cancel, Export) are clicked by label within `AppWindow::export-dialog`; the segments are `FFSegmented::segment` N counted over the whole window (Format TIFF, PNG, JPEG are 0-2; Chroma subsampling 4:4:4 and 4:2:0 are 3-4, present only for JPEG), the button label is the segment text and checked=true marks the selected one; `FFSegmented::root` 0 is the whole Format row (05 step 12 clicks its centre, the PNG segment). Checkpoint rows add `FFCheckpointRow::trash` (label **Delete checkpoint**), present only while the row is hovered.
Gotchas:
- A fixture fuse always ends in `AppWindow::divergence-warning` (the aligner cannot register the `mantis-64` frames), so the checkpoint exists only after **Keep**. `--fuse-tabs 0,0` raises the dialog twice, because the second press waits until the first is answered.
- Each **Keep** lands in the editor, whose toolbar has no **Fuse stack**; **STACKING** (`FFModeSwitch::stacking-half`) brings it back. The CHECKPOINTS list and **Export image** are present in both modes.
- **Export image** is greyed out until a result is kept, and a modal dialog blocks it; greyed or enabled is read with `buttons` within `FFDock::checkpoint-panel`, not from a screenshot.
- Every modal dialog except "Keep this fused result?" and the refusal dialog (`AppWindow::refusal-dialog`, titled "This project cannot be opened", "No frames here" or "These are not the project's frames") also has a **Close dialog** icon button (`FFIconButton`) at its top-right corner that does what the dialog's own Cancel (or Close) does; click it by that label within the dialog's id (`click "Close dialog" AppWindow::close-guard`); a footer button named "Close" is a different element. The export dialog's icon button is `buttons AppWindow::export-dialog`'s **Close dialog**.
- Rows have no per-row ids beyond `FFCheckpointRow::area N` (N counts from 0 in list order, separators excluded). The trash icon is `FFCheckpointRow::trash`; it shows only while the pointer is over a row and only while the list holds 2 or more rows; the hover is a `Hover` on a row (04 steps 21, 24 and 27).
- `FFMenu::root`, `FFMenuList::option-area` and `FFToggle::area` are counted over the whole window; with the export dialog open in a kept-fuse tab, `FFMenu::root` has 2 matches (0 Bit depth, 1 Compression), `FFMenuList::option-area` has one per option of the open list (Bit depth 16-bit, 8-bit; Compression None, LZW, Deflate) and `FFToggle::area` has 2 (0 the bottom bar's overlay switch, 1 Metadata); all verified live for 05-export.md steps 6-11.
- Four export sentences exist: "Exporting the unsaved fuse result held in this tab." (after a kept fuse), "Exporting your current unsaved retouch edits." (after a brush stroke, 05-export.md step 19), "Exporting the unsaved retouch checkpoint held in this tab." (after **Save checkpoint** with no brush stroke since, with or without a project file; 05-export.md step 24) and "Exporting the saved checkpoint you selected." (only with a project saved to disk; not covered).
- `--export-dialog-preview writing` and `--export-dialog-preview refused` set literal text with nothing behind it and need a launch of their own; their buttons (Cancel, Export, a format segment, **Close**, **Locate frames…**) may not respond. They are not part of a journey: the writing state ("Writing image…", progress bar, "Writing mantis-512-checkpoint-3.tif — this can take a few minutes for a large stack.") and the refused state (red "Can't export this position", lines "mantis_014.tif — missing" and "mantis_037.tif — changed since this checkpoint was fused", **Close**, **Locate frames…**) are read by launching with that flag.
