# Close and quit
Reach: with a fused project that has no project file yet (open a folder, press **Fuse stack**, answer **Keep**), click the tab's close glyph, or the **Close** control at the right end of the tab strip.
Sub-features: the close question raised at launch by `--request-close` (after the fuses settle and the active tab's **Keep** is answered); the unsaved-project note "Saving asks where to write the project file."; tab-close question ("Save this state first?": Cancel, Save and close, Close anyway); quit question ("Quit without saving?": Cancel, Save all and quit, Quit without saving) counting several projects ("2 projects have unsaved work."); a modal question blocks the controls under it.
Not covered, because each ends the run or needs a state a single launch cannot give: closing the window at once when nothing is unsaved (no question); closing a tab that holds nothing unsaved (no question); the empty state after the last tab closes ("No project open", "Open…"); `--request-quit`.
Gotchas: `--request-close` acts on the active tab (the last index in `--fuse-tabs`) once the last fuse has settled and its **Keep** question is answered; with `--fuse-tabs 0,1` the 8-frame tab is active, the fuses start at launch (the second takes up to a minute), and the close question follows within seconds of **Keep**. Each tab keeps its own **Keep** question: the first tab's (3 frames, "00.tif and 02.tif could not be aligned and were fused as they are.") appears only once that tab is selected, and a tab not yet kept holds no checkpoint, so closing it asks nothing. Two `--open` folders both give a tab titled "frames": tell them apart by the dock header ("3 frames" / "3 frames · 0 excluded" for mantis-64, "8 frames" / "8 frames · 0 excluded" for mantis-512; the short form shows in editor mode, which **Keep** enters, and the long form in STACKING mode), the first `--open` being tab 0. The mode switch is global, not per tab; the Images and Settings tabs exist only in STACKING mode. The tab-close confirm button reads "Close anyway". **Keep** is what creates the unsaved checkpoint the questions are about, and **Discard** leaves nothing to ask. Tab ids: `FFTab::area` 0/1 selects a tab, `FFTab::close-area` 0/1 closes it (2 matches with two tabs, verified live). Both questions are `AppWindow::close-guard`; click their buttons by label within it; the quit question appears about 2 s after **Close** (`FFTabStrip::window-close`). **Save and close** and **Save all and quit** open a native file chooser (human only); whether the question stays open after the chooser is cancelled is not known, so the next step re-raises it. A window or process ending is seen only as the driver finding no window, so the journey ends with **Quit without saving**; every cancel path comes first.
Escape: pressing Escape while a close question (`AppWindow::close-guard`) is open dismisses it as **Cancel** does: the window and the tabs stay (06 step 11). No click is needed before the `Press Escape` step.
Corner control: Every modal dialog except "Keep this fused result?" and the refusal dialog (`AppWindow::refusal-dialog`, titled "This project cannot be opened", "No frames here" or "These are not the project's frames") also has a **Close dialog** icon button (`FFIconButton`) at its top-right corner that does what the dialog's own Cancel (or Close) does; click it by that label within the dialog's id (`click "Close dialog" AppWindow::close-guard`); a footer button named "Close" is a different element.
